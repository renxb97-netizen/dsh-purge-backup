## 一、这个备份里有什么

```
dsh-purge-community-1.6.60-20261029-1604\
├─ 01-安装包\
│    └─ dsh-purge-community-1.6.60.tgz      ← 官方原始安装包（1.7 MB），最关键

├─ 03-配置备份\
│    ├─ package.json                        ← DSH 的插件登记文件（含依赖 + bundles 列表）
│    ├─ cordis.patch.yml                    ← 插件注入补丁
│    ├─ pnpm-lock.yaml
│    └─ cordis.yml
├─ 04-运行状态\
│    ├─ prompt-inject.md                    ← 你现在的提示词注入内容

│    └─ （其余为 dsh-purge 的运行状态文件）
```

`01-安装包` 和 `02-已安装副本` 是**互为备份**的两份：tgz 是官方原包（可被 pnpm 正常识别），
解压副本是不依赖包管理器、直接丢进 `node_modules` 就能跑的那份。

## 二、恢复方法（推荐：一键）

1. **先完全退出 DSH**（托盘也要退，确认任务管理器里没有 `DeepSeekRuntime` 进程）；
2. 右键 `一键恢复.ps1` → **使用 PowerShell 运行**；
   （若提示脚本被禁止，先在 PowerShell 里执行一次：
   `Set-ExecutionPolicy -Scope Process Bypass -Force`）
3. 看到 `✔ 恢复完成` 后，重新启动 DSH。

脚本做的事：
- 把 tgz 放回 `%USERPROFILE%\.dsh\dsh-purge-community\pkgs\f742c17f…\`
- 把插件复制回 `%USERPROFILE%\.dsh\profiles\desktop\node_modules\dsh-purge-community`
- 修正 `profiles\desktop\package.json` 里的依赖路径（自动换成当前用户名）和 `bundles` 列表
- 缺状态文件时补回 `04-运行状态` 里的内容

## 三、恢复方法（手动，脚本跑不通时）

```powershell
# 1) 建目录并放回安装包
$pkg = "$env:USERPROFILE\.dsh\dsh-purge-community\pkgs\f742c17f8f0bcd95501b7a4123c2283ebe2f135fe44ad1339fb928e0eeabc6c1"
New-Item -ItemType Directory -Force -Path $pkg | Out-Null
Copy-Item ".\01-安装包\dsh-purge-community-1.6.60.tgz" $pkg -Force

# 2) 直接放解压副本（最省事，不依赖 pnpm）
$dst = "$env:USERPROFILE\.dsh\profiles\desktop\node_modules\dsh-purge-community"
New-Item -ItemType Directory -Force -Path (Split-Path $dst) | Out-Null
Copy-Item ".\02-已安装副本\dsh-purge-community" (Split-Path $dst) -Recurse -Force
```

然后编辑 `%USERPROFILE%\.dsh\profiles\desktop\package.json`，确认这两处：

```json
{
  "dependencies": {
    "dsh-purge-community": "file:C:/Users/<你的用户名>/.dsh/dsh-purge-community/pkgs/f742c17f8f0bcd95501b7a4123c2283ebe2f135fe44ad1339fb928e0eeabc6c1/dsh-purge-community-1.6.60.tgz"
  },
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app", "dsh-purge-community"] } }
}
```

保存后重启 DSH 即可。启动后在会话里让它执行一次 `purge_status`，能看到 80 patch 的状态就说明装回来了。

## 五、注意事项

1. **别在 DSH 运行时覆盖插件目录** —— 文件被占用会写失败；先退干净再恢复。
2. **升级 DSH 主程序后**，插件可能需要重新 `purge_apply` 一次（DSH 版本变了，注入锚点要重打）。
3. 这个备份是 **1.6.60** 版，对应 DSH `0.2.1-rc.1`。以后 DSH 大版本升级，若插件报锚点不匹配，
   需要新版本插件；届时可以把 `02-已安装副本` 留档，作为"能跑的老版本"。
4. 想更保险：把整个 `dsh-purge-backup` 目录再复制一份到 U 盘/网盘/另一块硬盘。
   建议至少保留两份物理介质。
